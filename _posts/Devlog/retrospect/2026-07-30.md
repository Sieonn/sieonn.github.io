## 💡 배운 점 / 인사이트

**가설 검증이 일관되지 않으면 완전히 틀린 방향으로 진행된다**
- 1차 가설: GridManager의 dynamicDataFilter가 타겟 그리드 선택 없이는 평가되지 않아서 캘린더 마운트 시 미평가 상태를 스냅샷한다고 판단. GraphManagerBase.tsx에 스냅샷 전 재시도 로직을 추가했으나 사용자 테스트 결과 효과 없음 (수정 되돌림).
- 실제 원인을 찾기 위해 브라우저 콘솔 디버그 로그(FPDEBUG 태그)를 추가해서 사용자의 재현 현장 로그를 수집한 후, 실제 로그 분석:
  - 다이나믹 필터는 이미 정상적으로 resolve 되어 있었음
  - 문제는 필터 값이 아니라 "캘린더 자신의 그리드 데이터가 0개"(total_rows: 0, calendar_rows: 0)였음

**비동기 데이터 로딩의 타이밍 문제는 "이벤트 대칭성"으로 감지**
- GraphManagerBase.tsx에서 hasSourceOnSamePage인 캘린더는 원본 그리드 데이터를 extractGridDataFormat()으로 그 시점에 스냅샷 복사
- 원본 그리드의 자체 데이터 로딩이 그보다 늦게 끝나면 빈 데이터를 복사해가는 race condition 발생
- postDataSaved 이벤트는 캘린더와 원본(같은 페이지) 그리드 모두에 등록되어 있었으나, postDataLoaded 이벤트는 비대칭: 캘린더의 sourceGrid에만 등록, 원본 그리드에는 미등록
- 원인 확정 후 비대칭을 제거해서 수정

**복잡한 초기화 로직은 "인과 맵"으로 추적**
- 캘린더 마운트 시점, 원본 그리드 데이터 로딩 시점, 필터 토글 시점, generateEvents() 호출 시점을 시간 순서대로 정렬해서 "언제 어느 이벤트가 발화하는가"를 매핑했을 때 문제가 명확해짐
