## 💡 배운 점 / 인사이트

- **autosquash rebase의 실용성**: 이미 staging된 변경사항을 이전 커밋에 효과적으로 병합할 수 있음. 커밋 히스토리 분할과 통합 사이의 유연한 균형점을 제공.

- **다층적 컴포넌트 버그의 패턴**: 캘린더(레이아웃), 폼(상태 관리, 데이터 유실), 그리드(UI 정합성, 마스킹)에서 동시에 버그가 발생하는 것은 우연이 아니라, 프레임·그리드·컴포넌트 계층 간 상태 동기화와 레이아웃 계산이 긴밀하게 얽혀있음을 의미.

- **마스킹·고정 영역의 버그는 국소 패치로 안 됨**: GridCell, GridLayer, GridSelectionContainer, BaseGridCore에서 선택 인디케이터 위치가 어긋나는 문제는 어느 한 지점의 z-index나 left값만 고쳐서는 안 되고, 고정 영역의 경계 정의부터 선택 박스 렌더링까지 전체 흐름을 함께 검토해야 함.

- **대규모 UI 제거는 검증 단계가 필수**: ViewGrid.tsx의 숨겨진 컬럼 목록 UI 제거(128줄)는 기능적으로는 완료되었지만, 관련 Cypress 테스트(FrameExpand, 컬럼 가시성)를 실행하기 전에는 staged하지 않는 신중함 필요.

## 🧱 어려웠던 점 / 막힌 부분

- **여러 계층의 버그 동시 처리 시 영향 범위 파악**: 캘린더, 폼, 그리드, 입력 컴포넌트가 동시에 버그를 가지고 있었기 때문에, 각각의 근본 원인과 수정 범위를 한 번에 판단하기 어려웠음. 결국 각 커밋별로 영향을 검증하는 방식으로 진행 (Cypress 수동 실행, 관련 컴포넌트 grep 등).

- **GridCell/GridLayer 마스킹 버그의 복잡도**: 고정(freeze) 영역의 경계와 선택 인디케이터 위치가 3곳에서 동시에 어긋나 있었음. 어느 지점에서 어긋났는지 특정하려면 canvas 렌더링, CSS mask, 좌표 계산을 모두 이해해야 했고, 수정 후에도 한 지점 변경이 다른 곳에 영향을 주진 않는지 재검증 필요.

- **폼 draft 데이터 유실의 근본 설계 문제**: EditableFormPage와 ViewFormPage에서 draft 상태를 각각 관리하고 있었기 때문에, 저장 실패 시 한쪽은 복구되고 다른 쪽은 손실되는 일관성 문제 발생. 이를 formDraftRecord, formLookupOptions 유틸로 중앙화했지만, 더 근본적으로는 폼 상태 관리 구조 재설계 여지 있음.

- **ViewGrid.tsx 리팩토링 검증 대기**: 숨겨진 컬럼 목록(FilterManualModal) 제거로 128줄이 삭제되었는데, 관련 테스트 실행 전까지는 의도하지 않은 회귀가 있을 수 있어 현재 unstaged 상태로 보류 중.
